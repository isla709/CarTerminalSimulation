# 竖屏连接配置与位置附加项（2026-10-21）

## 连接布局

- 平台连接默认收起地址、端口、终端手机号和协议版本，摘要显示目标、连接状态、手机号与版本。连接、断开、取消和保存按钮保持可见。
- 展开配置沿用按实际可用宽度排列的字段网格，浮动标签预留顶部空间；收起时释放键盘焦点。连接期间锁定会话身份字段，防止编辑值和活动会话不一致。

## WPF 行为对应

依据当前 `TerminalSimulation.Wpf/MainWindow.xaml` 的标准附件区域、`MainViewModel.cs` 的 `SimulationTimerCallback`，以及 `MainViewModel.Protocol.cs` 的 `ReportLocationAsync`，不是旧文档推断。

| 01 | 里程 | 4 | 0.1 km |
| 02 | 油量 | 2 | 0.1 L |

- 与 WPF 一致，默认开启 01、03、30、31；默认信号 31、卫星 15，其他数值为 0。记录速度默认同步主速度，发送快照按主速度 ×10 截断。
- 每秒累加 `速度 / 3600 × 10` 的里程，按 `速度 × 百公里油耗 / 100 / 3600 × 10` 消耗油量，保留小数余量。与 WPF 一样按一秒回调推进，不在 UI 卡顿后突发追赶。模拟选项与是否携带该附件独立；只有附件开关决定发送与否。
- 信号/卫星每秒各有 30% 概率进行 -1、0、+1 变化，并限定范围。停止路线并不关闭这些独立开关；当前主速度参与计算，符合 WPF 原有定时器行为。
- 增加数值范围与有限数校验；里程到 uint32 上限后饱和、油量最低为 0。编辑中的无效文本不静默变为 0，模拟跳过无效草稿；发送或保存时明确提示错误。

## 自定义 RAW

- 独立 ID、长度、数据 HEX 字段，接受空白、短横线和竖线分隔。先拼接标准 TLV，再按列表顺序拼接 RAW。保留重复 ID，不经过 Map 去重。
- 长度字段不强制等于数据长度、不自动补齐或修正；空字段不添加字节，保留 WPF 的协议异常构造能力。“按数据填入长度”是显式操作。
- 与 WPF 原实现的区别：无效 HEX 阻止整帧发送，不在异常后继续发送残缺附件。单个草稿字段限制 4096 字符，最多 128 行；最终全部附件最大 995 字节，加 28 字节位置固定体不超过 1023 字节。RAW 的 ID 和长度不是强制单字节，便于保持原样注入能力。
- 标准项和 RAW 分组默认收起；展开后宽窗多列、窄窗单列。位选择弹窗支持滚动和窄宽度重排，支持 HEX 预览。

## 配置

- “保存配置”将附件开关、数值、模拟选项与 RAW 列表存入本机 `settings.json` 的 `locationAttachments` 对象；不保存鉴权码。
- 支持独立 JSON 导入/导出。字段名与 WPF 配置对应，导入接受 WPF 完整 `config.json`、仅含自定义项的工作状态 JSON 或 Flutter 设置中的附件对象，仅替换附件配置。缺省字段使用 WPF 默认值。导入有结构、数值、HEX、大小校验，整体成功后才替换；之后须保存以保留到重启。
- 不迁移插件的附件追加事件；平台连接、注册身份和其他 WPF 配置字段不由此导入。

## 折叠输入框异常修复

- 通过本机 VM 服务捕获首次展开连接配置的首条 `Flutter.Error`，根因是 `ScrollPosition.restoreScrollOffset` 从 `PageStorage` 读到了 `bool`，随后发生 `_elements.contains(element)` 连锁断言。折叠面板的 `PageStorageKey` 保存展开状态，内部没有独立存储标识的输入框共享了这个标识，并把布尔值当成滚动偏移 `double` 读取。
- 公共 `EditField` 为每个实例持有独立 `ScrollController(keepScrollOffset: false)`，传给 `TextFormField`，并随字段一起释放。输入框滚动位置只保留到当前编辑器生命周期，不再读取面板的展开状态；面板本身仍保留折叠状态记忆。没有替换错误界面或屏蔽框架断言。
- Windows Debug 重建成功，Dart 静态分析无问题。实际展开连接配置、聚焦服务器字段、收起并重新展开，三个输入框与协议选择正常；标准附加项展开正常。此轮本地交互观察期间未捕获新的 `Flutter.Error`。未新增或运行自动化测试，未连接或发送任何平台报文。
- 构建日志 `bin/Debug/windows-collapse-fix-build.log`；首次异常与修复后观察分别位于 `bin/Debug/windows-collapse-framework-errors.jsonl`、`bin/Debug/windows-collapse-fixed-framework-errors.jsonl`。另有既存 Windows 无障碍引擎 `Announce message viewId` 提示，与本次字段类型冲突不同，尚未修复。
