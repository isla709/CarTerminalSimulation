# 工具工作台与报文日志（2026-10-21）

## 入口和状态

工具页统一仅保留报文分析、HTTP、数据透传和 JT1078 入口，各功能使用独立二级页面。分析输入与结果、HTTP 请求草稿及响应、透传编辑草稿在本次应用会话内保留。HTTP 工作空间通过显式保存写入 `http-workspace.json`，支持 `CTS-HTTP/1` JSON 导入/导出，不自动导入原 WPF 工作空间格式。

## HTTP

- 请求新建、复制、删除，最多 100 个；查询参数和请求头逐项启用/禁用，正文单独编辑。宽窗请求/响应分栏，小窗切换请求/响应；工作空间采用宽屏侧栏或抽屉。
- GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS、UTF-8 正文与 Content-Type、1–300 秒超时、取消；取消、退出及旧请求完成后不回写新页面状态。
- 响应状态/耗时/字节数、正文/响应头/原始 HEX、UTF-8/GBK 重新解码、JSON 格式化、复制完整正文、保存完整原始字节。原始响应上限仍为 10 MiB；HTTPS 使用系统证书，不放宽校验，不自动重定向。
- 工作空间最多 4 MiB，单个请求正文 256 KiB；大正文解码/JSON 格式化放在 isolate 中，预览布局限 64 Ki 字符并按行创建，HEX 预览限 16 KiB。完整字节仍可保存。JSON 格式化单独限制为 4 MiB。

## JT808 数据透传

- 0x0900 上行、0x8900 下行和 0x8300 文本消息，保留原始字节、方向、时间及透传类型/文本标志，发送与显示编码分别选择 GBK、UTF-8 或 HEX。
- 聊天式记录、自动滚动、内容与 HEX 复制、填回编辑器、记录导出。发送前验证十六进制类型和长度，单帧内容最多 1022 B；未连接和发送中禁用发送按钮。记录最多 500 条。
- 当前工作台对应 JT808 平台透传；原生串口后端仍未移植，不把本页称为已经完成 WPF 串口桥接。

## 手机布局

- HTTP 的 URL 独占一行，方法与发送按钮按可用宽度排列；不足时完整换行。取消入口仅在请求进行时显示。请求名称与超时放入“请求设置”，首次在手机宽度打开时默认折叠，后续保留用户的展开选择。
- 请求/响应使用全宽切换，手机标签固定为“参数 / 请求头 / 正文”和“正文 / 响应头 / HEX”，不依靠横向滚动寻找标签。参数和请求头逐项显示启用状态、删除入口及名称/值，窄屏时输入框上下排列。
- 透传在手机宽度默认进入发送编辑区，消息记录单独切换；连接状态、记录数和记录菜单形成紧凑工具栏。发送类型与编码等宽排列，内容编辑区使用剩余空间，底部提供字节计数和全宽发送按钮。桌面保留同时显示记录与编辑区的方式。
- 页面始终保持同一滚动容器与编辑器层级，键盘弹出、横竖屏变化时不迁移输入控件。展开设置或高度不足时允许纵向滚动；手机隐藏桌面快捷键提示。
- 本轮通过 Dart 静态分析及 Windows Debug 构建，并在实际 Windows 窗口约 270、320、390 宽度查看 HTTP、参数编辑及透传布局。日志：`bin/Debug/mobile-workbench-windows-build.log`。未运行自动化测试；手机输入法、系统字号与安全区仍需 Android/HarmonyOS 真机复查。

## 日志

- 对照 WPF 保留通信/系统分组、来源与关键词筛选、自动滚动、清空全部、整条及 RAW 复制。跨平台范围排除了插件，因此没有插件分类入口。
- 暂停只冻结显示，接收继续；支持 Ctrl/Shift 多选、Ctrl+C、筛选结果导出和原始报文详情。宽窗右侧详情，小窗进入二级详情页。
- 选中报文在后台自动解析，串行任务、32 条缓存；需要表格/树状/字节字段操作时直接送入同一报文分析工作台，原始 HEX 无需手工复制。解析失败仍保留原始帧。解码范围沿用 [分析边界](windows-detail-iteration.md)，不等同于 WPF 协议库全部解码器已移植。
- 历史由 AppModel 独立保存，最多 2000 条且消息/RAW 估算合计不超过 8 MiB；超过时淘汰最旧项并计数。普通文本单条限制 8192 字符。刷新合并为 50 ms；隐藏或被覆盖的页面不跟随每条报文重建，解析不在接收回调内同步执行。

## CEF 日志洪泛修复

本轮发现默认原生 `debug.log` 已增至 **78,486,294,492 字节（约 73.1 GiB）**，导致 D 盘空间耗尽。已保存 32 KiB 尾部脱敏诊断到忽略目录，清空该生成日志后恢复空间；没有清理源代码、地图 Key 或签名。

根因：`webview_cef 0.6.2` 在插件注册时就启动 vblank 线程，尚未 `CefInitialize` 即反复向不存在的 CEF UI 线程投递任务，持续输出 `No task runner for threadId 0`。显示状态变化时 `WaitForVBlank` 可能立即返回，使循环速率进一步放大。

Windows 的 `cef_compat.cmake` 在构建目录修补固定版本依赖，公共 Pub 缓存不变：

- 初始化成功后才启动刷新线程，退出前先停止；即使 vblank 立即返回也至少按 4 ms 间隔推进。
- 记录真实初始化结果，失败时返回错误，避免重复初始化和未初始化即 Shutdown；页面初始化失败允许重新尝试。
- 默认关闭 CEF 无上限文件日志，保留 CTS 有界应用日志和显式帧诊断。原生开发排查可显式打开 CMake `CTS_CEF_FILE_LOGGING`，该模式不用于日常试用。
- 保留先前 GPU 描述符生命周期补丁。补丁定位失败会中止构建，依赖升级时须复核。
