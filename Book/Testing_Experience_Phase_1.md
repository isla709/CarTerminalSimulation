# 阶段性测试经验归档 (Phase 1 Testing Summary)

本归档记录了在项目早期开发阶段，为验证技术可行性和协议解析机制所编写的一系列测试脚本及其研究成果。随着主工程的完善，这些独立的测试脚本当作历史经验归档于此，原文件已被安全清理。

## 1. 视频流 NALU 单元分割测试 (`TestJT808` 经验总结)

**背景与目的**：
在对接 JT1078 实时视频流传输协议时，我们需要将获取到的原始 H.264 视频流实时切分成 NALU（Network Abstraction Layer Unit）以便进行后续的打包、推流或者播放处理。考虑到流媒体处理对性能要求极高，我们编写了专门的基准测试脚本来验证手动分割 H.264 Start Code 的算法效率。

**核心结论与经验**：
- **Start Code 特征**：H.264 的 NALU 分割符主要有两种特征：`0x00 00 01` (3字节) 和 `0x00 00 00 01` (4字节)。
- **高效遍历算法**：通过在内存字节数组中进行手动指针/索引遍历，直接扫描 `0x00 00 01`，并向后回溯一字节判断是否为 4 字节的 Start Code。这种一次性遍历法（O(n) 时间复杂度）避免了多次内存拷贝和复杂的正则表达式匹配。
- **性能指标**：对于 1MB 左右的数据块，手动截取并生成 `List<byte[]>` 的耗时在毫秒级别，完全满足 JT1078 实时音视频推流中的高并发处理需求。这也是我们在最终代码中选择手动实现 NALU 分界解析而非依赖沉重第三方库的理论支撑。

## 2. 协议反射与数据结构探测 (`test_analyze` 经验总结)

**背景与目的**：
由于使用了开源的 `JT808` 解析库，库中封装了大量关于部标 JT808/JT1078 的消息体。为了在不查阅庞大源码的情况下快速了解各个类的可用属性，我们编写了一系列反射分析脚本（包括 `test_analyze` 项目，以及 `test_0x008x.cs`, `test_0x8103.cs`, `test_jt808.cs`, `test_jt808_2b.cs`, `test_types.cs` 等离散文件）。

**核心结论与经验**：
- **反射分析工具**：利用 `System.Reflection`，我们直接打印出了 `JT808_0x8103_0x0081` 到 `0x0084` 的全部强类型字段；并且遍历了 `JT808_0x8103_BodyBase` 的所有子类，摸清了终端控制指令（0x8103）的全部派生结构。
- **扩展附加信息**：对 `0x0200`（位置信息汇报）的附加信息（如 `0x02`, `0x2A`, `0x2B` 等扩展状态）进行了探测。
- **指导后续开发**：这帮助我们快速厘清了底层框架对于复杂消息体的字段映射关系，为后续我们在 WPF 的 `MainViewModel` 和 `Protocol` 层编写终端心跳、参数上报、鉴权以及音视频属性交互提供了准确的数据模型定义依据。

## 3. 杂项基础测试与日志排查 (`test_regex`, `test_nalu.cs`, `app_crash.log` 等)

- **其他 NALU 解析草稿**：如 `test_nalu.cs`，不仅测试了分割，还探测了 NALU Type（解析第 5 字节的低 5 位 `nalu[4] & 0x1F`），验证了关键帧和非关键帧的区别。
- **日志分析**：在开发初期曾保留过 `app_crash.log` 作为异常崩溃的记录，后续通过完善的 `try-catch` 及 WPF 全局异常捕获体系已完全取代了静态日志排查。
