# 车载定位终端模拟系统 (JT808 / JT1078)

欢迎使用**车载定位终端模拟系统**。本项目是一个基于 Windows Presentation Foundation (WPF) 开发的现代化模拟终端软件，旨在高度模拟真实的 JT808 协议车载定位终端设备以及 JT1078 音视频流媒体设备，实现与后端平台及流媒体服务器的无缝通信。

> **当前版本特性**
> 涵盖了核心的 JT808 终端注册、鉴权、位置汇报、数据透传、地图路径模拟功能，并**深度集成了 JT1078 实时音视频推流引擎**，搭载了全面定制化的现代 UI 与丝滑体验。

---

## 🚀 核心功能特性

### 1. 协议通信与连接支持 (JT808)
- **多版本协议**：支持 **JT808-2013** 与 **JT808-2019** 双协议版本切换。
- **自定义连接**：可配置服务器 IP、端口、终端手机号以及鉴权码。
- **基础指令**：支持标准的**终端注册**与**终端鉴权**流程。
- **心跳保活 (0x0002)**：支持自定义心跳发送间隔，也可随时关闭自动心跳。

### 2. 详细的位置汇报 (0x0200)
- **手动上报与自动循迹**：支持单次手动发送位置汇报，也支持设定时间间隔进行循环发送。
- **动态坐标模拟**：实时指定经度、纬度、速度、方向（0-359度）及高程数据。
- **位标志配置**：图形化勾选设置各项**报警标志**与**车辆状态标志**。

### 3. 高质量视频推流引擎 (JT1078)
- **多通道并发推流**：支持配置最高 **36路** 逻辑视频通道，各通道可独立运行、独立预览并独立推流。
- **原生文件支持与智能转码**：
  - 支持直接选取本地常见视频格式 (`.mp4`, `.avi`, `.mkv` 等)。
  - 内置 FFmpeg 引擎自动下发**工业级标准转码**：强制重制为 `25 FPS`, `2秒 GOP(关键帧间隔)`, `1Mbps码率` 的标准 H.264 裸流，彻底免疫第三方视频源因关键帧稀疏导致的 HLS 切片卡顿、慢动作、掉帧及 404 问题。
- **平台远程控制指令拦截**：
  - 支持解析 **0x9101**（实时音视频传输请求）指令，响应平台并自动拉起对应通道的流媒体推送。
  - 支持解析 **0x9102**（音视频传输控制）指令，接收平台的关闭通道命令（包括 `ChannelNo = 0` 的批量关闭操作）并安全中断连接。
- **实时流量与断线监控**：
  - 支持单通道实时推流速率 (KB/s, MB/s) 与总消耗流量监控，以及全局多通道总流量大盘汇总。
  - 精准的底层 Socket 异常捕捉，被动断网时自动销毁内部数据流并重置 UI 状态。
- **本地视频预览**：基于底层 LibVLCSharp 提供稳定流畅的各个通道流媒体预览视图。

### 4. 高级功能面板
- **通信日志**：实时呈现终端与服务器之间的上下行报文记录，支持自动滚动和一键清空。
- **数据透传**：支持多种编码格式（GBK、UTF-8、HEX）的数据透传发送与接收，类似聊天的气泡界面，直观区分服务端与终端消息。
- **配置导入/导出**：一键将当前的终端参数及设定项导出为 JSON 文件，并在需要时快速导入恢复。

### 5. 交互式地图与路径模拟 (基于 Leaflet + WebView2)
- **内置地图视图**：内嵌高德地图，可直接在地图上选点来获取经纬度。
- **地图风格切换**：提供多种地图滤镜风格（如午夜深蓝、灰度模式等）。
- **动态小车航向**：小车图标会根据输入的 `Direction` 角度参数进行实时自适应旋转。
- **路径规划及样式**：支持多路径规划显示，可切换如“青蓝霓虹”、“紫粉赛博”等充满科技感的动态路径渲染样式。

### 6. 极致现代化的 UI 界面
- **材质设计 (Material Design)**：全系统采用 MaterialDesignInXamlToolkit，拥有丝滑的点击水波纹、悬浮卡片阴影等现代视觉体验。
- **深浅模式与主题色**：支持明亮与暗黑模式一键切换，自带丰富的系统级主题颜色选择。
- **半透明玻璃与亚克力效果**：支持插入自定义背景壁纸，并自由开启普通半透明、毛玻璃 (Blur) 和亚克力 (Acrylic) 模糊效果，同时可调节板块的透明度。

## 🔬 技术特点与技术方案

### 1. 高并发异步 TCP 推流方案 (JT1078)
JT1078 视频推流的底层实现面临着高并发与碎片化封包的挑战。为保证高频送流不阻塞 UI 且网络极其平滑：
- **微包聚合 (MemoryStream Buffer)**：每一帧视频往往需被切割为数十个 950 字节的微包。相较于在 `while` 循环里疯狂调用 `await NetworkStream.WriteAsync` 导致线程池饥饿与 TCP 窗口震荡，本系统采用了内部 `MemoryStream` 内存聚合，每帧几十个 RTP 数据包序列化后会在内存中合并为单个 Payload，最后仅进行 **单次 WriteAsync 级系统调用** 送入 OS 套接字，彻底消除了巨量 I/O 上下文切换的开销。
- **高精度时间线调度 (SpinWait 机制)**：摒弃了 C# 原生易引发 15ms 线程阻塞的 `Thread.Sleep(1)` 反模式。采用了带有缓冲区延时的 `Task.Delay` 配合尾部纳秒级的 `SpinWait.SpinUntil` 混合等待机制，在不榨干 CPU 的同时，实现了对 25 FPS 等精确物理帧推送频率的完美卡点。
- **抗 32位 PTS 溢出的绝对时间戳保护**：对 JT1078 的 `Timestamp` 发生器进行了深层优化。采用基于系统墙上时钟 `DateTimeOffset.UtcNow` 与帧间精准自增浮点累计双路防漂移机制，并防止因 13 位 Unix 毫秒乘 90kHz 后在部分流媒体服务区底层产生的 32-bit PTS 寄存器溢出问题。

### 2. FFmpeg 视频管道自动化
- 结合 `Xabe.FFmpeg` 包装器实现了自动环境检查、自动依赖下载及全自动强制转码逻辑。
- 强制设定了 `-c:v libx264 -preset ultrafast -r 25 -g 50 -b:v 1M -an -f h264` 编码参数管道，一劳永逸地解决用户自带视频源关键帧跨度太大引发的服务器端切片超时现象，保证了 HLS 下游切片极速秒出与播放器的防卡顿体验。

### 3. MVVM 架构与 CommunityToolkit 应用
- 客户端使用现代 C# 特性与 `.NET 8.0` 构建，采用了微软官方最新的 `CommunityToolkit.Mvvm` 进行开发。
- 大量运用了 `[ObservableProperty]` 和 `[RelayCommand]` 源代码生成器 (Source Generators)，极大地精简了前台界面的数据绑定代码与事件触发逻辑，提升了开发与执行效率。

### 4. 混合 WebView 的 GIS 数据展示
- 基于 `Microsoft.Web.WebView2` 集成 Chromium 内核。
- WPF 后端与 JS 前端使用安全桥接技术实现双向数据流。C# 计算的 GPS 坐标可以以极低延迟驱动前端高德地图/Leaflet 层的小车移动，实现流畅平滑的动态轨迹动画反馈。

## 🛠️ 技术栈

- **主框架**: .NET 8.0 WPF
- **UI 库**: MaterialDesignThemes (Material Design in XAML)
- **协议栈解析**: 基于标准 JT808 格式规范自行封装以及第三方核心反序列化组件
- **视频底层转码**: Xabe.FFmpeg & 嵌入式 FFmpeg 二进制环境
- **视频本地预览**: LibVLCSharp
- **网络通信**: 基于高阶 async/await 的 TCP Socket 连接
- **地图引擎**: WebView2 + HTML5/JS (Leaflet.js + 高德地图服务)
- **架构**: MVVM 驱动模型 (CommunityToolkit.Mvvm)
