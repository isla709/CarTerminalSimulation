# Preview11 系统日志与轨迹模拟入口

原“地图选点”入口改为“轨迹模拟”，包括主页面标签、过渡遮罩和 old/new Web 面板标题。只改变名称，`MapProvider: old/new`、选点/导航、坐标系、保存文件及独立历史路径不变。

原“通信日志”页面改为“系统日志”，顶部提供三个独立分类复选框：

| 分类 | 内容 |
| --- | --- |
| 通信日志 | 发送、接收、收发解析、网络、协议、解析异常、心跳、自动汇报、音视频及其控制 |
| 系统日志 | 系统状态、配置、地图、更新、媒体处理等其他组件日志和通用异常 |
| 插件日志 | 通过宿主插件上下文发出的消息、插件加载审计与插件自定义消息操作 |

默认全部勾选。可只勾选一种，也可任意组合；“全部”恢复三个分类。全部取消时显示空结果提示，不删除历史。每条记录保留原始来源标签，分类是单独元数据，不通过列表文字动态判断。

“显示 x / y 条”分别为筛选结果与保留历史数量；最多保留整个进程最近 2000 条。所有分类共享这个上限，不保证每类各留 2000 条。筛选选项本次运行有效，暂不增加配置字段。

“清空日志”清空全部分类的日志，不只是当前筛选结果。原清空命令同时清理透传消息列表的既有行为保留。复制 RAW 报文和复制整条日志继续可用。自动滚动只跟随当前可见记录，关闭后不因已排队的滚动回调跳到底部。

## 实现

- `Services/ApplicationLog.cs`：纯数据的进程级有界历史、顺序号、时间、来源、类别和原始报文。收集不依赖是否打开控制台。
- `ConsoleLogger`：统一发布日志后按需输出控制台；因此地图初始化、更新检查等原来仅到控制台的消息也能进入页面。
- `MainViewModel.Log`：仅经过统一日志入口，不重复追加 UI 记录。插件 `IPluginContext.Log` 保持原签名，按插件分类进入相同管线。
- `ViewModels/SystemLogViewModel.cs`：WPF `ListCollectionView` 筛选，后台突发消息只排一个待执行刷新，再从有界历史同步，避免消息数量直接变成 Dispatcher 回调数量。
- `Views/CommunicationLogView.*`：保留内部类名以降低无关改动；工具栏可换行，列表虚拟化，过滤后的集合驱动自动滚动。

日志分类由来源入口决定；使用插件 SDK 的日志自动归为插件。第三方插件若绕过宿主直接打印标准输出或把日志声明为普通系统来源，不能自动识别其调用者身份；没有新增插件沙箱或跨进程日志捕获。

## 验证入口

`SystemLogTests` 覆盖来源分类、有界保留、RAW 复制数据、单选/组合/全空筛选、隐藏记录恢复、后台洪峰合并刷新、清空及释放。`WpfViewSmokeTests` 覆盖 480/1100 DIP 宽度的日志布局与页面构造；双地图仍使用 `Scripts/Test-MapUi.cjs new/old` 离线回归。
